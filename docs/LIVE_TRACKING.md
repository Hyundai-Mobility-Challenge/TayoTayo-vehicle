# Pleos 내비 기준 하원 위치 공유

2026-11-03 수정. 차량의 실제 Pleos 내비 관측값을 기준으로 사용한다. 독립 카카오 길찾기와 배경지도 로딩은 추적 흐름에서 제거했다. 외부 지도 키는 필요하지 않다. 기존 인계 확인과 하차 기록은 유지한다.

## 현재 표시하는 정보

- 실제 방문 순서와 내 아이 픽업 지점, 남은 정류장 수, 차량의 마지막 Pleos 수신 위치.
- 내비 목적지와 내 아이 픽업이 일치하고 그 아이가 다음 정류장인 경우에만 Pleos의 남은 거리·시간을 표시한다.
- 부모 앱과 앱 없는 임시 보호자의 웹 화면은 같은 아이 범위 데이터를 사용한다. 다른 아이 이름·주소·정류장 좌표·내비 목적지·원본 routeId/routeIndex를 응답에 포함하지 않는다.
- 부모 앱에서 `오늘 픽업 링크 공유`로 Android 공유 선택창을 연다. 실제 메시지를 자동 발송하지 않는다. `내가 만든 공유 모두 종료`로 발급 링크를 취소한다.

## SDK 관측과 ETA 검증

현재 설치: NaviHelper 3.0.5 / navi-data 3.0.4.

- `getCurrentLocationInfo` / `onCurrentLocationInfo`: 위도·경도, routeId, currentRouteIndex. 센서 측정 시각이 아닌 SDK 콜백 수신 시각을 저장한다.
- `getDestinationInfo` / `onDestinationInfo`: 목적지 좌표, remainTime, remainDistance. 현재 다음 정류장 한 곳씩 `requestRoute`로 안내하는 기존 구조를 유지한다.
- `onRouteStarted`, `onReRouteEnded`, `onRoutingCompleted`, `onDestinationChanged`, `onRouteOptionChanged`, `onWaypointChanged`, 취소/오류/안내 모드 변경 시 이전 관측을 무효화한다. 새로운 위치·목적지 관측이 모여야 ETA가 재개된다.
- 위치와 목적지 관측이 30초 이내이고 routeId가 서로 일치해야 한다. 다음 정류장과 아이의 정류장 순서가 같고 내비 목적지가 픽업 좌표 5m 이내일 때만 ETA를 내보낸다. 나머지 경우 eta=null이다.
- 남은 시간은 SDK 수신 이후 경과 시간을 차감한다. 정류장 인계 대기 시간을 측정한 값이 아니므로 화면에서 별도라고 알린다. 뒤 순서 아이에게 다음 아이의 ETA를 재사용하거나 직선거리로 대신 계산하지 않는다.
- `SIMULATION_GUIDING`은 모의 위치·ETA로 명시한다. 합성 시험 데이터는 실제 주행 검증이 아니다.
- SDK 정보 콜백에는 요청 상관 ID가 없다. 재탐색 후 늦게 오는 응답의 순서와 목적지/경로 식별자의 실제 갱신 방식은 실기기에서 추가 검증해야 한다. 콜백 누락이나 routeId 미제공 시 ETA를 숨긴다.

## 지도와 경로선의 한계

현재 부모 앱/웹은 **OpenStreetMap 배경지도에 Pleos 차량 위치와 내 픽업 장소를 표시한다**. 실제 Pleos 안내 경로선은 아직 제공하지 않는다. 받은 차량 좌표를 도로선 위로 강제로 옮기거나 임의의 연결선을 경로로 표시하지 않는다. 운행 전에는 로그인한 보호자의 연결된 어린이 픽업 장소만 표시하며 차량 위치·ETA·공유는 만들지 않는다.

검사한 NaviHelper 공개 API에는 전체 도로 polyline을 반환하는 메서드가 없다. TripSummary.routePoints는 POI/경유 지점, TrafficInfo는 교통 비율 정보이고 RouteOverviewShowInfo는 화면 표시 시간이다. requestNavigationScreen은 차량 내비 화면 요청이며 부모 폰용 지도 컴포넌트/웹 타일 API가 아니다. 따라서 정확한 Pleos 도로 경로선과 부모 폰에서 동일한 배경지도를 사용하려면 Pleos가 지원하는 경로 좌표·외부 지도 표시 범위를 확인해야 한다. 지도/SDK 자체를 복제·배포하지 않는다.

`server/road_routes.py`는 외부 공급자가 없는 폐기 안내 모듈이다. 기존 지도 환경변수가 남아 있어도 서버는 사용하지 않는다. `/api/tracking/config`는 navigationSource=PLEOS_NAVI, geometryAvailable=false만 반환한다.

## 차량 앱이 배경으로 이동할 때 (현재)

- 첫 실행 권한 안내 후 위치·차량 속도·알림 권한이 유지되면, 연결된 SDK 운행의 출발 버튼에서 `TripTrackingService`가 자동 시작된다. 기관 화면에서 별도 전송 동작을 요구하지 않는다.
- foreground 알림을 표시하고 읽기 전용 NaviHelper·AAOS 구독과 약 5초 전송을 유지한다. 순정 내비를 열어 Activity가 onStop 되어도 계속된다. 문 제어·인계 기록을 배경에서 실행하지 않는다.
- 운행 종료·범위 이탈·권한 회수 때 중단한다. START_NOT_STICKY이며 강제 종료/부팅 후 몰래 시작하지 않는다. OS가 종료하면 수신측은 30초 후 갱신 대기로 전환한다.
- D 전환은 설치된 Pleos `requestNavigationScreen(Foreground)`로 화면을 요청한다. GPS 미수신이어도 화면 열기는 가능하며 도착 판단은 별도의 엄격한 위치·경유지·정차 검사를 통과해야 한다.
- 근접 정차 알림은 HIGH/CATEGORY_NAVIGATION으로 제공한다. 탭은 현재 운행·정류장·경로 버전과 일치할 때만 앱 화면을 연다. 인계와 하차 기록을 만들지 않는다. 임의 오버레이 권한이나 배경 Activity 강제 실행을 추가하지 않았다.
- 이번 실제 AVD에서 사용자가 권한을 허용했고, 운행 시작/배경 내비 전환 중 실제 위치·ETA 전송을 확인했다. 근접 도착 알림의 실제 표시와 OEM 팝업 정책은 미검증이다.

## 공유 보호

로그인한 보호자의 아이 연결과 해당 운행 탑승 기록을 확인한다. 링크는 256비트 토큰이며 서버에는 SHA-256만 저장한다. 아이·운행·발급 보호자로 범위를 제한하고 최대 4시간 또는 운행일 한국 자정 중 먼저 도래하는 때 만료된다. 하차, 운행 종료, 전송 끄기, 보호자 연결 해제, 새 운행으로 교체되면 기존 링크를 차단한다. 재연결로 이전 링크가 살아나지 않는다.

토큰은 URL fragment로 전달하고 페이지 시작 후 주소에서 지운다. 조회는 Authorization 헤더를 사용하며 no-store/no-referrer, iframe 금지, 요청/토큰 비로깅을 적용한다. 공유 링크는 위치 조회만 허용하고 어린이 인계 권한을 부여하지 않는다. 기관의 기존 확인 절차를 따른다.

## 실행과 검증

1. 기존 기관/차량/부모 연결 절차는 [기관 연결 안내](INSTITUTION_DEMO.md)를 따른다.
2. 서버와 차량/부모 debug APK를 업데이트한다. 기존 로그인·운행 데이터 삭제는 필요 없다.
3. 차량 최초 권한을 허용한 뒤 오늘 명단/탑승을 준비하고 SDK 모드에서 운행 시작을 누른다. 위치 전송이 자동으로 켜진다.
4. Pleos가 내비 목적지·위치·routeId·남은 시간을 실제로 제공하는지 확인한다. 부모 카드에서 내 아이가 다음 픽업일 때만 내비 ETA가 나타나야 한다.
5. 순정 내비 화면을 연 뒤 서버 갱신이 계속되는지, 종료/끄기 후 갱신이 멈추는지 확인한다.
6. 개발 링크는 PC 서버에 접근할 수 있는 같은 내부망에서만 사용한다. 다른 휴대폰에서 127.0.0.1/10.0.2.2는 사용할 수 없다. 외부망은 별도 공용 HTTPS 운영 서버가 필요하다. 이 작업에서는 배포·터널·방화벽·새 계정/키 설정을 하지 않았다.

```powershell
python -m unittest discover -s server -v
node scripts/test-route-map.cjs
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug :app:assembleDebugAndroidTest :parent:assembleDebug :parent:lintDebug :parent:assembleDebugAndroidTest
python scripts/serve-tracking-fixture.py --output "$env:TEMP\pleos-tracking-fixture" --port 8791
# fixture.json URL은 합성 관측 전용. mode.txt live/stale/revoked/ended로 전환.
adb -s TEST_DEVICE shell am instrument -w -r -e class com.hanhyo.shuttle.parent.TrackingUiTest com.ssafy.tonghak.parent.test/androidx.test.runner.AndroidJUnitRunner
```

삼성폰 UI 검증은 화면이 깨어 있고 사용자가 잠금을 풀어야 실행된다. 잠긴 상태의 raw code -4는 skip이며 통과가 아니다. 기기 설정/잠금을 테스트가 바꾸지 않는다.

최종 로그와 결과는 `evidence/tracking/pleos-correction/`에 저장한다. 이전 카카오/직선거리 문서·시험 결과는 수정 전 기록이며 현재 기능 설명으로 사용하면 안 된다.

공식 근거: [NaviHelper](https://document.pleos.ai/en/docs/pleos-only/connect-sdk-pleos/NaviHelper/intro), [이벤트](https://document.pleos.ai/en/docs/pleos-only/connect-sdk-pleos/NaviHelper/event-listeners), [Android 위치 foreground service](https://developer.android.com/develop/background-work/services/fgs/service-types#location), [서비스 시작 조건](https://developer.android.com/develop/background-work/services/fgs/launch).

## OpenStreetMap 배경지도 (2026-11-03 사용자 승인 후 추가)

- 앱 어린이 카드에 지도 표시, 확대 보기, 확대/축소, 드래그 이동, 차량·픽업 전체 보기. 공유 웹도 같은 렌더러를 사용한다. 갱신 지연은 회색 차량 마커로 표시한다.
- `common/web/route-map.js`는 Web Mercator 좌표와 현재 화면의 타일만 요청한다. 확대/이동은 사용자 조작만 따르며 자동 지역 다운로드·오프라인 저장 기능은 없다. 같은 위치 갱신은 이미지 노드를 재사용하고 HTTP 캐시 기본 동작을 유지한다. 실패 시 안내와 재시도 버튼을 제공한다.
- 배경지도 출처와 저작권 표시를 항상 보여준다. 외부 스크립트나 경로 검색 API는 사용하지 않는다. 화면에 필요한 지도 타일 번호와 일반 네트워크 정보가 OpenStreetMap에 전달되며, 어린이 이름·공유 토큰·이벤트 기록은 보내지 않는다.
- 공유 페이지는 fragment를 즉시 지우며 API 요청은 Bearer/no-referrer를 유지한다. 지도 이미지에만 `referrerPolicy=origin`을 사용해 OSM에 페이지 경로나 토큰 없이 origin만 전달한다. Android는 앱을 식별하는 User-Agent와 기본 WebView 캐시를 사용한다. 위치 권한을 보호자 폰에 추가 요청하지 않는다.
- 링크 만료·철회·페이지 숨김 시 지도 인스턴스와 표시를 제거한다. 서버의 자녀별 접근 제어 및 링크 수명은 그대로다.
- OSM 표준 타일은 제한된 개발 시연용으로 사용한다. 서비스 보장이나 무제한 사용 권한이 아니므로 실제 배포 전 이용 규모에 맞는 지도 제공자/호스팅과 개인정보 안내를 정해야 한다. 운영 HTTPS 배포는 수행하지 않았다.
- 사용 정책: https://operations.osmfoundation.org/policies/tiles/

## 차량 앱에서 연결하기

- 기본 하원 화면의 `보호자 지도 · 위치 공유`에서 누락된 준비 단계를 확인하고 `기관 연결 · 위치 전송`으로 이동한다.
- 차량 연결 코드는 차량 앱, 어린이 초대 코드는 보호자 앱에서 사용한다. 차량 연결 후 `배정 명단으로 운행 준비`가 필요하다.
- 준비 중 연결 방식에서 `Pleos 내비 연동` 또는 `모의 체험`을 명시적으로 선택한다. 명단 로드는 기존대로 모의 체험으로 시작한다.
- 실제 지도·안내 경로는 `Pleos 내비 지도` 버튼으로 순정 차량 내비를 연다. 보호자 앱의 OSM 배경지도로 차량 내비를 대체하지 않는다.
- 탑승 기록과 운행 시작 후 위치 전송을 켠다. SDK 모드에서는 사용자가 정확한 위치 권한을 허용해야 한다. 권한을 자동 부여하지 않는다.
- 모의 체험의 `시험용 위치 1회 전송`은 기관에 연결된 현재 운행, 탑승 아동, 진행 중인 하원 지점이 있어야 활성화된다. 위치만 보내며 실제 ETA·도착·인계·하차를 생성하지 않는다. 30초 뒤 갱신 지연으로 바뀐다.
- 화면을 벗어나도 실제 SDK 전송 서비스는 운행 중 유지되며, 모의 1회 전송은 별도 자동 갱신하지 않는다. 운행 종료나 공유 끄기는 기존 만료 규칙을 따른다.


## 정차 상태에서 움직이는 지도 시연 (2026-11-03)

1. 기관 차량 연결과 배정 명단 불러오기를 완료한다. **모의 체험**으로 준비하고, 어린이 탑승을 기록한 뒤 운행을 시작한다. 보호자 폰은 같은 서버의 해당 어린이와 연결되어 있어야 한다.
2. 차량 앱 `기관 연결 · 위치 전송`에서 위치 전송을 켜고 **이동 시연 시작**을 누른다.
3. 현재 픽업 지점으로 90초간 이동하는 가상 좌표가 약 5초 간격으로 전송된다. 보호자 앱·공유 웹의 차량 마커가 이동하며 `모의 위치`, `모의 내비 시험값`을 표시한다. 지도 마커는 갱신 사이 화면상 보간하므로 실측 궤적이 아니다.
4. `일시정지`는 위치를 유지하고 ETA를 숨긴다. `시연 계속`은 같은 위치부터 이어가며, `시연 종료`는 위치와 ETA를 제거한다. 네트워크가 끊기면 수신 화면은 30초 후 갱신 지연으로 표시한다.
5. 가상 좌표가 끝에 도달해도 도착·인계·하차 기록은 생기지 않는다. 선생님이 기존 확인 절차로 진행한다. 다음 지점·경로 변경, 운행 종료, 공유 끄기, 차량 앱을 벗어나기는 시연을 중지한다. 다음 지점은 다시 명시적으로 시작한다.
6. 보호자 카드의 공유 버튼으로 위치 확인 링크를 만들 수 있다. 앱 없는 임시 보호자가 같은 내부망에서 열어 지도와 익명 정류장 진행을 확인한다. 링크가 인계 권한을 부여하지는 않는다.

시연은 앱 내부 합성 좌표이며 Android/Pleos GNSS, 순정 내비 경로, 실제 차량 속도를 바꾸지 않는다. 이동 경로는 도로와 일치하지 않을 수 있고 임의의 경로선은 그리지 않는다. 실제 Pleos 모드에서는 현재 내비 목적지가 내 아이 픽업일 때만 SDK ETA를 표시하며 이후 정류장의 ETA를 추측하지 않는다. 전체 Pleos 도로 경로선은 공개 SDK 데이터가 없어 여전히 미지원이다. 익명 정류장 진행은 양쪽 화면에서 볼 수 있으나 다른 어린이 이름·주소는 전달하지 않는다.

이번 변경 검증: `evidence/tracking/moving-demo/RESULTS.txt`.


## 정류장 진행 바와 체험 운행 전환 (2026-11-03)

- 기관 연결이 되어도 현재 `fictional-*` 체험 운행이 기관에서 불러온 운행과 다르면 위치 전송은 켜지지 않는다. `기관 연결 · 위치 전송 → 체험 보관 후 기관 명단 준비`로 기존 로컬 체험을 보관하고 연결된 기관 명단을 불러온다. 실제 기관 운행, SDK 운행, 저장 오류, 전송 중 상태는 이 단축 전환 대상이 아니다. 연결 코드를 재발급할 필요는 없다.
- 기관 명단에서 탑승 기록 → 운행 시작 → 위치 전송 켜기 → 이동 시연 시작 순서로 진행한다. 기존 인계·하차 절차는 그대로다.
- 보호자 앱과 공유 웹의 기본 화면은 `출발 → 정류장 1 → … → 내 아이 하차` 세로 진행 바다. 다른 어린이의 이름·주소·좌표는 표시하거나 전송하지 않는다. 지도는 별도 `지도 보기/지도 크게 보기`에서 열 수 있다.
- 버스 아이콘은 각 구간에서 처음 수신한 ETA 대비 남은 ETA 비율로 표시한다. 위치나 도로 이동 궤적이 아니며, 시간만 0이 되어도 방문 완료를 만들지 않는다. 다음 정류장은 차량 앱의 실제 운행 순서 변경에 따라 전환한다. 재탐색/경로 변경 시 진행 기준을 새로 잡는다.
- 다음 정류장 ETA는 그 정류장과 실제 내비 목적지가 일치할 때만 표시한다. 내 아이가 뒤쪽이면 실제 도착 시간은 확인 중으로 유지한다. `demo-*` 명시적 시연에만 이후 구간 90초·정차 20초 가정으로 내 아이 시연 시간을 합산하며 표시 문구로 구분한다.
- 30초 이상 갱신 지연, 일시정지, 내비 재탐색 시 진행 애니메이션과 ETA를 중지한다. 이 진행 바는 인계 권한이나 도착 확인을 대신하지 않는다.


## 보호자 폰 디자인·도착 완료 연동 (2026-11-03)

- 라이드 공식 승하차 화면의 흰 목록, 노란 운행 상태 띠, 번호 정류장·세로선·버스, 완료 배지 구성을 참고했다. 참고: https://www.ride.bz/assets/images/feature-boarding-2611.webp 및 https://docs.ride.bz/menu/parents/ . 로고·이미지 자산은 앱에 복사하지 않았다.
- 보호자 앱의 지도·지도 버튼을 제거하고 네이티브 Compose 정류장 목록으로 교체했다. 메인 화면은 어린이, 운행 상태, ETA, 정류장 진행, 공유 순서다. 초대 연결은 추가 연결 항목, 푸시 설정과 로그아웃은 알림·설정, 과거 기록은 접을 수 있는 최근 하원 기록에 배치했다.
- 차량에서 내 아이 지점의 `도착·정차 확인`을 누르면 서버의 ALIGHTING/현재 정류장을 기준으로 보호자 `ARRIVED` 상태가 된다. 버스가 내 하차 지점에 도착하고 인계 대기 문구가 나타난다. 단순 ETA 0초로 도착을 확정하지 않는다.
- `인계 확인 → 하차 기록` 후 보호자 본인에게만 `COMPLETED`와 완료 시각, 익명 정류장 순서가 남는다. 차량 위치/ETA는 반환하지 않으며 기존 공유 링크는 즉시 종료된다. 운행 종료만으로 어린이 하차를 만들어내지 않는다.
- 완료 기록은 해당 일자의 기록이다. 새 운행이 등록되면 이전 완료 상태를 재사용하지 않는다. 미연결 보호자나 공유 링크에는 이 완료 영수증 API를 허용하지 않는다.
- 폰 화면은 약 5초 polling으로 차량 기록을 반영한다. 차량 전송과 합쳐 수 초 지연될 수 있다. 이번 범위는 보호자 폰 우선이며 공유 웹 디자인은 별도다.

- 위치 전송을 꺼도 차량이 확인한 내 아이 정류장의 도착 상태는 로그인한 보호자에게 표시한다. 이 경우 위치·ETA·공유 버튼은 제공하지 않으며, 미탑승 아동이나 다른 정류장의 도착을 대신 표시하지 않는다.


## 세 정류장·출발 알림·Pleos 경유지 ETA (2026-11-03)

- `python scripts/add-demo-stops.py`는 기존 햇살유치원 데모 차량에 가상 지우(덕수궁 대한문), 가상 서연(DDP)을 중복 없이 추가한다. 민수와 기존 연결·운행 기록은 변경하지 않는다. 현재 운행은 명단의 스냅샷이므로 운행 종료 후 `기관 연결 → 배정 명단으로 운행 준비`를 눌러 새 3명 명단을 받는다.
- 세 명 탑승 기록 → `순서 바꾸기`에서 **덕수궁(지우) → DDP(서연) → 서울숲(민수)**로 정하기 → `이 순서로 · 운행 시작`을 누른다. 자동 제안은 직선거리 기준으로 달라질 수 있으므로 민수가 마지막인지 확인한다. 보호자에게는 `정류장 1 → 정류장 2 → 내 아이 하차`만 보인다.
- 모의 체험: 위치 전송 켜기 → 이동 시연 시작. 이후 구간 90초·정차 20초 가정은 화면과 알림에 시연용으로 표시한다. 도착·인계·하차는 사람이 기존 버튼으로 확인한다.
- Pleos 연동: 운행 준비에서 `Pleos 내비 연동` 선택. 실제 안내 요청은 `requestRouteWithWaypoints`로 다음 3곳(경유 2곳 + 목적지 1곳)을 **승인된 운행 순서 그대로** 전달한다. 세 곳을 초과하면 이후 지점의 ETA는 해당 지점이 조회 범위에 들어올 때까지 확인 중이다. 별도 지도 공급자나 임의 출발지-목적지 행렬 조회를 사용하지 않는다.
- `getWaypointInfo / onWayPointInfo`의 `remainTime`, 최종 `DestinationInfo.remainTime`을 동일 내비 경로의 누적 시간으로 받는다. 위치/경로 식별자, 경유지 전체 순서·좌표·신선도가 모두 맞을 때만 아이별 ETA로 공개한다. Pleos가 반환한 남은 시간을 분 단위 올림으로 표시한다. 별도 정차 시간이나 관측 후 경과 시간을 가감하지 않으며 새 관측이 도착하면 갱신한다. 다른 아이 좌표/이름·원본 내비 경로 식별자는 보호자/공유 웹에 보내지 않는다.
- 출발 알림은 실제 DRIVING 전환과 해당 아이의 탑승 기록을 기준으로 운행당 한 번 만든다. 첫 ETA 응답을 최대 약 15초 기다리고, 없으면 `도착 시간 확인 중`으로 안내한다. 기록 전송 재시도/서버 재시작은 새 알림을 만들지 않는다. 전달 전 재조회해 큐에 오래 남은 숫자를 보내지 않으며 하차·운행 종료·연결 해제 후 출발 알림은 취소한다.
- 보호자 앱에 출발 시각과 내 아이 예상 시간이 보이며 약 5초마다 최신 서버 응답으로 바뀐다. 앱이 백그라운드이면 FCM 출발 알림을 누르면 현재 화면이 열린다. OS 알림 허용 및 기존 FCM 서버 구성이 필요하다.
- Pleos의 완료 이벤트 순서가 다르더라도 새 `RouteStateInfo`에서 안내 중·탐색 종료가 확인되면 기존 관측을 버린 뒤 새로운 위치·목적지·경유지 응답을 받는다. 재탐색/잘못된 목적지/오래된 경유지 응답은 ETA를 유지하지 않는다.

SDK 근거: NaviHelper 3.0.5, navi-data 3.0.4의 설치된 공개 클래스와 [공식 경유지 요청 문서](https://document.pleos.ai/en/docs/pleos-only/connect-sdk-pleos/NaviHelper/route-with-waypoints). `TripRequest`는 목적지 좌표만 받고 임의 출발지나 경유 목록을 받지 않으므로 하원 지점 간 시간 행렬로 사용하지 않는다.

### 등록 좌표 보완과 실제 내비 시간 (2026-11-03 최종)

Pleos Connect v2.1.0 AVD는 경유지 이름·remainTime과 최종 목적지 좌표는 반환하지만, 중간 경유지 latitude/longitude는 0.0, display 좌표는 null로 반환했다. 이제 **동일 경로의 전체 경유 순서·고유 이름, 유효한 최종 목적지 좌표, 최신 위치/routeId가 모두 일치**하면 좌표가 0인 중간 지점만 기관에 등록된 좌표로 보완한다. 잘못된 비영점 좌표, 이름 중복, 순서 불일치, 최종 목적지 좌표 누락은 보완하지 않는다. 보호자에게 다른 어린이 이름이나 좌표는 전송하지 않는다.

시간은 실제 `onWayPointInfo/getWaypointInfo` 및 `DestinationInfo.remainTime` 관측값이다. 별도 정차 30초 가산을 제거했다. 기기 시계만 흐른다고 실제 ETA를 감소시키지 않으며 새 SDK 관측으로만 숫자를 갱신한다. 30초 넘게 오래되면 표시하지 않는다. 현재 정류장이 완료되면 남은 경유 목록을 다시 요청하고 재탐색 동안 이전 ETA는 숨긴다. 다음 정류장 시간만 뒤쪽 아이의 시간으로 재사용하지 않는다.

실제 AVD 가상 정류장 시험에서 3개 누적 시간 `[2520,3000,3540]`, 이후 2개 `[2760,3360]`, 마지막 1개 `[2460]`의 네이티브 응답과 격리 보호자 API 전달을 확인했다. 이 최초 시험은 정차 가산 제거 전이었으므로 당시 보호자 숫자는 60/57/41분이었다. 최종 가산 제거 후 서버·Android 전송 및 삼성 화면 테스트를 통과했다. 최종 네이티브 재시험은 기존 활성 내비 경로를 보존하기 위해 건너뛰었다. 정차/재출발을 포함한 실제 도로 주행 및 FCM 수신을 이번 시험으로 입증하지 않는다.

이 방식은 Pleos의 경유지 좌표 응답을 고치거나 가상 GPS로 내비를 움직이는 기능이 아니다. 시연용으로 빨리 움직이는 버스는 `모의 체험`을 사용한다. 자세한 조작은 [DEMO_STEP_BY_STEP.md](DEMO_STEP_BY_STEP.md), 증거는 `evidence/tracking/registered-stop-eta/`를 참조한다.

## 자동 운행·알림과 일반 기록 조건 분리 (2026-11-03)

일반 기록·순서·출발 검사는 최신 속도 0/P/연결/SDK 출처와 차량 UX 제한을 확인한다. 주차브레이크 조건은 `doorStationaryBlockers`로 분리해 문 제어 시험에만 적용한다. 실제 UnlockSafetyPolicy와 문 장치 제어 검사는 완화하지 않았다.

접근(APPROACHING)은 아이별 최신 ETA 0~2분, 도착(ARRIVED)은 해당 아이 정류장의 ALIGHTING 확인으로 생성한다. 새 안내는 출석 상태를 바꾸지 않는다. 운행/아이/종류로 중복을 막고, 발송 직전 연결·탑승·경로 버전·내비 경로·최신 ETA를 재검사한다. 오래된 큐와 하차/연결 해제 뒤 알림은 취소한다. FCM TTL은 접근·도착 60초다. 가상 시간은 시연용으로 표시한다.

현재 차량/부모 앱은 최초 권한 안내 이후 운행마다 재요청하지 않는다. 서버·폰의 실제 알림 증거와 한계는 `evidence/tracking/trip-flow/`에 보관했다.
