## 사용자 결정과 AI 제안의 구분

사용자가 정한 것 (2026-11-01 대화):

- 디자인 시스템은 기존 것 대신 새 차량용 룩, 이후 **라이트 모드(흰 바탕)**로 전환
- 운행 범위는 **등원·하원 모두**
- 형태는 **가로 전체화면**과 화면 분할 시 **세로형** 두 가지
- **동요 선택 화면** 추가
- '순서를 정한 기준'은 매번 보여줄 필요가 없음 — 처음 한 번이면 충분
- **순서 바꾸기** 기능과 부족한 화면 보강
- (2026-11-02) 캔버스 px → dp 환산은 **×1.3** — 에뮬레이터 앱 창 측정 근거는 [TOKENS.md 단위](TOKENS.md#단위)

AI 제안이라 팀 확인이 필요한 것:

- 흐름 단계 구성(오늘의 통학 → 경로 → 승차 → 이동 → 하차 준비 → 정차·인계 → 복귀 → 종료 점검)
- 색·글자·크기 수치, 노란색을 채우기에만 쓰는 규칙
- 보호자 미도착 선택지 3가지(전화 · 3분 대기 · 동승 유지)
- 주행 중 잠금 범위, 보호자 도착 알림, 아이 상세·인계 가능자, 운행 기록, 이번 주 노래

## 가상 데이터와 자리표시

어린이 이름, 정류장, 시간, 곡명, 정류장 메모, 이동 시간은 모두 가상 예시다. `[확인 필요]`, `[곡명]`, `[보호자 이름]`, `[메모 예시]`는 연동 방식이나 실제 값이 정해지지 않은 자리다.

## 검증 범위

캔버스는 게시만 했고 렌더링과 프로토타입 동작은 검증하지 않았다. `code-drafts/`의 순수 Kotlin 계산은 이 문서를 만들 때 따로 컴파일·실행해 본 결과를 [code-drafts/README.md](code-drafts/README.md)에 적었다. 앱 빌드·에뮬레이터 실행·실차 확인은 하지 않았다.
