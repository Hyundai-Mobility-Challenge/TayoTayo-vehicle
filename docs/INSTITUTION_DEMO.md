# 통학메이트 · 여러 기관과 보호자 초대 데모

이 폴더의 기존 차량 앱에 기관 연결 기능을 더하고 `parent` Android 모듈과 `server`를 추가했다. Git 원격에 제출하거나 클라우드에 서버를 배포하는 작업은 포함하지 않는다.

## 구성

| 구성 | 역할 |
|---|---|
| `app` | 기존 Pleos Compose 앱. 차량 코드로 연결, 배정 명단으로 운행 준비, 기기에 확정 저장한 승하차 원장을 서버로 전송 |
| `parent` | 공용 보호자 앱. 가입/로그인, 초대 코드 수락, 연결된 여러 어린이와 기관 조회, 로그인 후 FCM 자동 등록 |
| `server` | Python HTTP 서버 + SQLite. 기관별 관리 웹, 인증/초대/차량 배정/기록 API, FCM 발송 대기열 |
| `common/kotlin` | Android 두 앱이 사용하는 HTTP 클라이언트 |

기관 → 차량/어린이를 관리하고, 보호자 ↔ 어린이를 연결한다. 보호자는 여러 기관의 어린이와 연결할 수 있다. 차량을 바꿔도 보호자 연결은 유지한다. 이미 시작한 운행은 당시 배정 명단의 사본을 유지하고, 변경한 배정은 다음 운행을 불러올 때 적용한다.

초대 코드는 **지정 이메일 + 24시간 + 한 번 사용** 조건이다. 재발급하면 같은 어린이/이메일의 이전 코드는 무효화한다. 차량 연결 코드는 10분이며, 새 기기가 연결되면 기존 차량 인증은 만료된다. 관리자가 보호자 연결을 해제하면 기록 조회와 아직 발송을 시작하지 않은 알림을 차단한다. 이미 발송 중이거나 FCM이 접수한 알림은 회수할 수 없다.

## PC 서버 실행

PowerShell에서 프로젝트 폴더를 연다. Python 3.11 이상을 사용한다.

```powershell
# 웹/명단/초대/기록만 시험할 때 (FCM 설치 불필요)
.\server\start.ps1

# 같은 내부망의 휴대폰과 FCM을 함께 시험할 때
.\server\start.ps1 -Push -ListenAddress 0.0.0.0
```

기본 포트는 **8790**이다. 기존 `car` 프로젝트의 8787 서버와 별개다. 관리 화면은 <http://127.0.0.1:8790/>이다.

`-Push`는 `server/.venv`를 만들고 `requirements.txt`를 설치한다. 기본 서버 키 경로는 `%USERPROFILE%/.config/tonghak/firebase-admin.json`이며 `-CredentialPath`로 바꿀 수 있다. 키는 서버에서만 읽고 앱이나 저장소에 넣지 않는다.

서버 데이터와 로그/PID는 Git에서 제외된 `server/data/`에 있다. 이 PC에서만 SQLite 파일로 기록하며 Firebase에는 FCM 발송을 요청한다. Firestore에 기관 명단을 저장하지 않는다. 스크립트는 방화벽 규칙, 포트 포워딩, 공인 서버 배포를 변경하지 않는다. 서버를 종료할 때는 `data/server.pid`의 PID가 이 프로젝트의 `server.py`인지 확인한 후 해당 프로세스만 종료한다.

## 체험 순서

1. PC 관리 화면에서 관리자 계정으로 로그인하거나 새 기관을 만든다.
2. 차량을 등록하고 어린이를 등록한다. 어린이 이름, 배정 차량, 정류장 이름/위도/경도를 입력한다.
3. 차량의 **연결 코드 만들기**를 누른다. 차량 앱의 **명단 · 상세 → 기관 연결**에 서버 주소와 코드를 입력하고 연결한다.
4. 차량 앱에서 **배정 명단으로 운행 준비**를 누른다. 기록 전 준비 상태 또는 운행 종료 상태에서만 가능하다. 이전 운행은 보관하며 미전송 기록이 있으면 교체하지 않는다.
5. 관리 화면에서 어린이와 보호자 이메일을 지정해 초대 코드를 만든다. 코드는 직접 전달한다. 문자/이메일 자동 발송은 구현하지 않았다.
6. 보호자 앱에서 동일한 이메일로 가입/로그인한 뒤 코드를 입력한다. 한 번 로그인하면 푸시 토큰을 자동으로 등록한다. 알림 권한을 허용한다.
7. 차량의 기존 흐름대로 **탑승 기록 → 운행 시작 → 도착·정차 확인 → 인계 확인 → 하차 기록**을 진행한다.
8. 관리 화면/보호자 앱에서 새로고침하면 기록이 보인다. FCM 설정이 있으면 연결된 보호자 기기에 하차 알림을 보낸다.

다른 기관의 어린이도 같은 보호자 이메일로 초대하면 보호자 앱 한 곳에 표시된다. 차량 변경은 어린이 카드에서 수행한다. 변경 뒤 새 운행을 불러오면 반영되며 보호자 재초대는 필요하지 않다.

## USB 없이 연결하기

- PC: `-ListenAddress 0.0.0.0`으로 시작한다.
- 휴대폰: PC에 접근 가능한 네트워크에서 `http://PC의내부IP:8790`을 개발용 서버 주소로 입력한다. USB 등록은 필요하지 않다.
- Android 에뮬레이터: `http://10.0.2.2:8790`을 사용한다.
- 일반 Play Store 배포판: 서버를 공용 **HTTPS** 주소에 배포하고 앱에 기본 주소를 설정해야 한다. 그러면 보호자는 주소를 입력할 필요 없이 가입/로그인과 초대 수락만 한다.

현재 개발 APK만 내부망 HTTP를 허용한다. release는 HTTPS가 필요하다. 앱 화면을 닫은 경우 notification payload는 FCM/Android가 표시한다. 알림 권한, 기기 인터넷 연결이 필요하다. 사용자가 설정에서 앱을 강제 중지한 상태는 일반적인 최근 앱 닫기와 다르다.

## 처리/복구와 한계

- 비밀번호는 salt + PBKDF2-SHA256, 세션/초대 코드는 해시로 저장한다. 서버가 모든 기관/역할/어린이 접근을 검사한다.
- 차량 앱의 기존 원장을 먼저 기기에 저장한 뒤 전송한다. 전송 실패 시 원장을 유지하고 앱이 열려 있을 때 5초 간격으로 재시도한다. 네트워크 복구 후 앱이 계속 닫혀 있으면 재실행해야 한다.
- 운행 ID + 원장 ID로 서버 중복 저장을 방지한다. 동일 어린이/운행의 첫 하차만 푸시 대기열을 생성한다. 기록과 발송 대상 생성은 하나의 DB 트랜잭션이다.
- FCM 발송은 최초 요청을 포함해 최대 5회 시도한다. `accepted`는 FCM 접수이며 실제 단말 수신/보호자 열람 보장이 아니다. 서버가 FCM 수락 직후 상태 저장 전에 종료되는 경우 재시도할 수 있으며 알림 태그는 이벤트 ID를 사용한다.
- 각 알림을 발송하기 직전에 기기 소유자와 어린이 연결을 다시 검사하고 `sending` 상태로 전환한다. 서버 재시작 시 중단된 `sending`은 총 5회 시도 한도 안에서 복구한다. 하나의 DB는 서버 프로세스 하나만 사용한다.
- 같은 보호자의 토큰이 바뀌면 아직 완료되지 않은 대기열을 새 토큰으로 옮긴다. 이미 접수된 알림을 다시 만들지 않는다. 발송 중 토큰 변경/서버 종료에서는 수락 여부가 불확실해 같은 이벤트를 재시도할 수 있다.
- 초대 수락 전에 생성된 기록은 앱에서 조회할 수 있으나 이전 알림을 새로 발송하지 않는다. 기기 토큰 변경은 다음 앱 실행/토큰 갱신에서 등록한다. 로그아웃은 서버 기기 연결 해제까지 성공한 뒤 처리한다.
- 현재 자체 계정은 **이메일 소유 확인을 하지 않는 로컬 데모**다. 실서비스에는 검증된 로그인/이메일·전화 인증, 기관 가입 심사/관리자 초대, 계정 복구, 보관·삭제 정책, 운영 감사/모니터링이 필요하다.
- Python 기본 HTTP 서버는 개발용이다. 공용 HTTPS 호스팅과 운영 서버 구성은 이번 작업에 포함하지 않았다.
- 출발지는 기존 서울시청 가상 예시이며 경로 계산도 기존 합성 직선거리 방식이다. 같은 이름/좌표의 정류장은 묶는다. 현재 서버 체험 명단은 차량당 1~6명이다.
- 기존 ‘도착 알림’ 스위치는 여전히 모의 설정이다. 이번 연결은 **확정된 하차 기록**에만 푸시를 보낸다. 잔류 감지/자동 인계/자동 하차 기능을 추가한 것이 아니다.

## 재현 가능한 검증

2026-11-02 이 PC에서 확인한 결과:

- 기존 차량 단위 테스트 **104개 통과**, 추가 서버 테스트 **11개 통과**.
- 차량/보호자 debug APK 빌드와 lint 통과. 차량 lint는 기존 포함 42개 경고, 보호자 lint는 0개 오류이며 경고는 보고서에 남겼다.
- Pleos API 34 에뮬레이터 통합 테스트: 차량 코드 연결 → 명단 불러오기 → 탑승 → 인계 없는 하차 거절 → 인계 후 하차 → 서버 전송 → 보호자 조회 통과. 최종 소스로 재실행해 통과했다.
- Samsung 실제 휴대폰 통합 테스트: `http://192.168.33.132:8790`에 직접 로그인 → 초대 수락 → 어린이 표시 → FCM 자동 등록 통과. 이 테스트의 API 통신에 `adb reverse`를 사용하지 않았다. USB는 APK 설치/테스트 실행 도구 연결에만 사용했다.
- 차량 테스트에서 생성한 하차 알림 2건은 각각 첫 시도에 FCM 접수되었고, 실제 휴대폰 알림 시스템에서 해당 이벤트 ID를 확인했다. 사용자가 새 하차 알림이 보인다고 확인했다. LTE/5G 및 장시간 대기 검증과는 구분한다.
- 관리 웹의 기관 로그인/초대 코드 발급/보호자 연결/FCM 발송 상태를 브라우저에서 확인했다.
- 결과 로그와 화면은 로컬 `evidence/institutions/`에 보관한다(Git 제외).

현재 가상 보호자 계정은 휴대폰에 로그인되어 있다. 차량 통합 테스트는 기존 기기 상태를 보존하도록 설정과 운행을 복원하므로, 직접 체험하려면 관리 화면에서 새 차량 연결 코드를 만들고 차량 앱의 **기관 연결**에 입력한다.

### 연결 예외 상황 추가 검증 (2026-11-02)

별도 임시 DB와 가짜 FCM 발송기로 서버 테스트를 24개로 확장했다. 실제 사용자 계정/차량/초대 코드를 변경하거나 테스트 푸시를 보내지 않는다.

- 어린이 한 명에 보호자 두 명 및 여러 휴대폰 연결, 한 휴대폰만 로그아웃해도 나머지 유지.
- 같은 휴대폰에서 보호자 계정 변경 시 이전 계정의 대기 알림 차단.
- 토큰 갱신 중 대기 알림 보존, 이미 접수한 알림 재발송 방지, 다른 보호자의 대기열 이동 차단.
- 발송 묶음 처리 도중 연결 해제 시 아직 시작하지 않은 알림 차단.
- 발송 중단 상태의 복구, 세션 만료 후 재로그인 시 어린이 연결 유지, 반복 실패 시 5회 한도.
- 별도 HTTP 서버 프로세스를 실제 종료·재시작하여 로그인/초대 연결/기록/대기열 유지와 요청 재전송 중복 방지 확인.
- 차량 배정 변경 후 기존 운행 재요청은 당시 명단 유지, 다음 운행에는 새 차량 배정 반영.

처음 실행에서 토큰 갱신 시 대기열 유실과 연결 해제 시 묶음 내 후속 알림 전송이 재현되어 수정했다. 발송 중 상태를 추가하면서 재시작 복구도 검사한다. 로그: `evidence/institutions/edge-cases-before.log`, `edge-cases-after.log`.

실제 단말에서 남은 확인: 잠금/장시간 대기, Wi-Fi↔모바일 데이터 전환, 알림 권한 거부/재허용, 앱 재설치·기기 변경, 차량 통신 중단 후 복구. 모바일 데이터에서 서버 API를 사용하는 시험은 공용 HTTPS 서버 등 접근 가능한 경로가 먼저 필요하다. 서버 단위 테스트 통과를 이 실기기 조건의 통과로 해석하지 않는다.

```powershell
python -m unittest discover -s server -v
.\gradlew.bat :app:assembleDebugAndroidTest :parent:assembleDebugAndroidTest
# APK/테스트 APK를 대상에 설치한 후, 기기별 주소로 실행
adb -s emulator-5554 shell am instrument -w -e class com.hanhyo.pleosshuttle.InstitutionDeviceTest -e serverBase http://10.0.2.2:8790 com.hanhyo.pleosshuttle.test/androidx.test.runner.AndroidJUnitRunner
```
